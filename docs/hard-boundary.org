#+TITLE: Hard boundary ABI
#+AUTHOR: Rohit Goswami

* Purpose

A LAMMPS-driven sampler can ask lammpc to apply a host-supplied region
constraint after every integration step. lammpc does not implement the
region and does not link rgsaddle. The host owns the geometry. lammpc
only transports the post-step positions, velocities, and box, then
applies the host decision.

The callback is off unless the host arms it. An unset callback adds no
fix and takes no coordinate snapshot.

* Decisions

The C callback returns one of three codes:

- =LAMMPC_BOUNDARY_ACCEPT= (0). The step stands. Writes the callback
  made in the position and velocity buffers are discarded, so the
  integrator state is unchanged.
- =LAMMPC_BOUNDARY_REJECT= (1). Positions and velocities are copied
  back from the pre-step state with =memcpy=. Constrained MD also restores
  its pre-step projected force, constraint force, and removed-velocity
  bookkeeping, but retains the consumed Langevin draws so the next proposal
  uses fresh noise. In the LAMMPS embed, image flags are restored with them
  and forces, energy, and virial data are refreshed at the restored state.
- =LAMMPC_BOUNDARY_REFLECT= (2). The host has already modified positions
  and velocities in place. Constrained MD restores the position and velocity
  constraints, then re-evaluates the force at that position; if that
  re-evaluation fails, the entire step rolls back. In the LAMMPS embed,
  forces, energy, and virial data are refreshed at the reflected state.

Any other code is an error. The pre-step state is restored and the
apply call returns -1. In the LAMMPS embed, the fix restores the
pre-step positions, velocities, and image flags and refreshes forces,
energy, and virial data before stopping the run.

* Callback

The callback type is =LammpcHardBoundaryFn=, declared in
=include/lammpc_boundary.h= together with =LammpcBoundaryBox=. This
callback rejects any step that leaves the box along z:

#+begin_src c
#include "lammpc_boundary.h"

int host_region(void *user, int n_atoms, double *positions,
                double *velocities, const LammpcBoundaryBox *box) {
  (void)user;
  (void)velocities;
  for (int i = 0; i < n_atoms; ++i) {
    const double z = positions[3 * i + 2];
    if (z < box->lo[2] || z > box->hi[2])
      return LAMMPC_BOUNDARY_REJECT;
  }
  return LAMMPC_BOUNDARY_ACCEPT;
}

const LammpcHardBoundaryFn host_region_fn = host_region;
#+end_src

=positions= and =velocities= each hold =3 * n_atoms= doubles in ascending
atom-tag order (tag 1 is index 0). Positions are angstroms. Velocities
are angstroms per picosecond. That is the metal-unit storage of a
LAMMPS instance, not the Hartree and Bohr force API.

=LammpcBoundaryBox= carries =lo=, =hi=, the restricted-triclinic tilts
=xy=, =xz=, =yz=, a periodic flag per axis, and =triclinic=.

=lammpc_hard_boundary_apply()= is the decision step itself. It is pure
C and does not need a LAMMPS instance. A NULL function pointer returns
accept and does not read the buffers.

Session entry points, on a live embed instance:

- =lammpc_session_set_hard_boundary()= stores the callback. NULL clears it.
- =lammpc_session_clear_hard_boundary()= clears it.
- =lammpc_session_integrate()= runs that many LAMMPS steps.
- =lammpc_session_md_step()= applies the callback once after every completed
  constrained-MD step.

The instance must already exist (a force evaluation builds it) and must
already have a time integrator and a timestep. A typical =extraSetup=
is =timestep 0.001= and =fix 1 all nve=. lammpc does not choose the
integrator.

* Region semantics

This is the same rule as a hard region on a sampler, without sharing
types or code:

- A point in the closed region is accepted. A planar signed distance of
  zero is inside.
- A planar crossing (positive penetration along an outward unit normal)
  is a reflection. The host mirrors the position through the face and
  reflects the velocity, then returns reflect.
- A predicate failure, where no penetration depth is known, is a
  rejection. Molecular dynamics returns to the previous contained
  state. Monte Carlo rejection is the same restore.
- The host may reflect more than once inside a single callback. lammpc
  calls the callback once per step.
- If the outward normal has no component in the active constraint, the
  host rejects and the previous state is restored.

For constrained MD, lammpc re-projects a reflected position and velocity onto
its configured plane before evaluating the next force. The host still owns
the hard-region geometry and any reflection normal.

* Velocity reflection

For an outward unit normal =n= and a constraint projector =P=:

#+begin_example
n_t = P n
n_t = n_t / ||n_t||
v   = v - 2 (v . n_t) n_t
v   = P v
#+end_example

The position is mirrored by the same normal and the penetration depth:

#+begin_example
x = x - 2 * penetration * n_t
#+end_example

An unconstrained slab uses the identity projector. In one dimension,
with outward normal +1 or -1, the normal component of velocity changes
sign and its square is unchanged, so kinetic energy is unchanged. The
analytic test uses that identity case.

* LAMMPS fix

The embed path registers style =lammpc/boundary= on the live LAMMPS
instance by inserting a creator into that instance's fix map. Nothing
is patched in the LAMMPS sources. The fix id is =lammpc_boundary= and
the group is =all=.

=lammpc_session_integrate()= adds the fix only when a callback is
armed, runs =run N=, and removes the fix before returning. The fix
mask is end-of-step, after the integrator and LAMMPS periodic
wrap. While the callback is unset, integrate does not add the fix and
does not snapshot positions or velocities.

Rejection writes the previous positions, velocities, and image flags,
then refreshes forces, energy, and virial data (=setup_minimal(1)= with
time-dependent computes re-scheduled on the current step) so thermo and
compute queries see the restored configuration. Reflection writes the
host position and velocity buffers, leaves image flags as LAMMPS set
them, and runs the same force, energy, and virial refresh at the
reflected configuration. An invalid callback code restores the previous
positions, velocities, and image flags and refreshes forces, energy, and
virial data before calling =error->all= to abort the run, so
=lammpc_session_integrate()= returns -1 with the live LAMMPS state
matching the restored pre-step configuration. Acceptance writes nothing.

The force loop (=lammpc_session_calculate_result= and =run 0=) does not
arm the fix. Arming happens only around =lammpc_session_integrate()=.

=lammpc_session_destroy()= forgets the host callback and disarms the
embed binding before it closes the LAMMPS instance. Disarm drops the
callback even when the fix is still installed, so a later step does
not call the host. A null instance is a no-op.

=lammpc_session_md_step()= keeps its own constrained position and velocity
state instead of installing the LAMMPS fix. When a callback is armed, each
completed constrained-MD step passes that post-step state and the live LAMMPS
box to the callback exactly once. Its positions are unwrapped under PBC.
Each step is transactional on failure: an invalid callback decision or a
failed force evaluation (either mid-step or after reflection) restores the
pre-step positions, velocities, projected-force bookkeeping, and Langevin
RNG before returning -1 without advancing =steps=. If the failed LAMMPS
evaluation lost atoms so the local atom count no longer matches the session
geometry, =md_ready= is cleared so a subsequent call cannot advance a
damaged instance until =lammpc_session_md_initialize()= rebuilds it.
Reject restores the pre-step constrained state and force bookkeeping while
retaining the consumed Langevin draws so the next proposal is fresh.
Reflect keeps the callback's writes, re-projects the position and velocity
onto the constraint plane, and re-evaluates the projected force. Rejected
steps count as successful =md_step= iterations; failed steps do not.

=lammpc_session_nve_step()= ignores the hard-boundary callback. It uses its
own LAMMPS =fix nve= path without adding =lammpc/boundary=.

* Rust

lammpc has no Rust API. There is no closure adapter. A Rust host calls
the C functions directly and passes a function pointer whose user
pointer reaches the closure.

* Analytic check

=tests/test_hard_boundary.c= is a stub-suite smoke test. It does not
build LAMMPS.

- A free particle in the slab =[0, 1]= with velocity +/- 1/2 stays
  inside for 16 steps of size 1/2. Kinetic energy after every decision
  equals the initial kinetic energy.
- A unit harmonic oscillator started at x = 3/8 with velocity 1, in
  the slab =[-1/2, 1/2]=, stays inside. On each reflection the kinetic
  energy of the velocity the callback sees is unchanged.
- A step that leaves the slab and is rejected restores both arrays
  with =memcmp=, including values the callback wrote before returning
  reject.
- Configurations landing on either closed slab face (=lo= or =hi=) are
  accepted without reflection or rejection.
- Accept discards in-place writes. Reflect keeps them. An unknown code
  restores the previous state and returns -1.
- A NULL callback does not dereference its buffers. The stub session
  entry points return -1 because no LAMMPS library is linked.

=tests/test_embed_lj_e2e.c= and =tests/test_embed_lammps_run0_e2e.c= link
=liblammpc.so=, which contains =src/lammpc_fix_boundary.cpp= and
=src/lammpc_boundary.c=. =tests/test_embed_precision_create_e2e.cpp=
includes =src/lammpc_embed_api.cpp= so it can read the live handle, and
the binary compiles those two companion sources with it. That test
checks force, energy, and virial refresh after reflect, reject, and
invalid callback decisions, verifies transactional step rollback when a
reflected =md_step= force evaluation fails, and checks that disarm stops
later steps from invoking the host.
=tests/test_embed_lj_e2e.c= also arms a reflecting callback before several
=lammpc_session_md_step()= calls and checks the callback, reflection, step,
and force-evaluation counts. Its rejection and reflection cases verify that
rejected force bookkeeping is restored, reflected state lies on the plane,
and the returned force is a fresh evaluation at the reflected position.
